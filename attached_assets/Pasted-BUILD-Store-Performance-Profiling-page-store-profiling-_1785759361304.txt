BUILD: Store Performance Profiling page (/store-profiling)

Goal: A page that profiles each retail store's performance vs. the last comparable period, gives an at-a-glance verdict (doing well / at risk / underperforming), and diagnoses the specific pain points hurting each store — across sales, targets, footfall/conversion, stock mix, sell-through, customer health, and range coverage.

IMPORTANT — reuse existing infrastructure, do not rebuild:

Read sales from all_sales (fields: pos_location_name, net_sales_kes, net_quantity, discounts_kes, gross_sales_kes, returned_item_quantity, customer_id, customer_type, sale_kind IN ('sale','order'), country, sale_date TEXT).
Exclude warehouse + pipeline + online locations using the existing WAREHOUSE_LOCATIONS, PIPELINE_LOCATIONS, BASE_FILTERS constants and the _sql_str() helper — same pattern as analytics_store_potential (line ~26523).
Targets: read from targets_monthly (scope='store', columns name, month, target_kes) — same as the monthly-targets endpoint.
Stock mix by range tier: call the existing range_mgmt_store_tier_mix() function — do NOT re-derive tiers; it already uses the single-source _lifecycle_tier.
Footfall: reuse /api/footfall logic (FootfallCam data) for traffic + conversion.
Store revenue benchmarking + maturity: reuse the approach in analytics_store_potential.
Sell-through by location: reuse /api/analytics/sell-through-by-location (line ~7979).
Customer health per store: reuse /api/customers-by-location (line ~6397).

NEW BACKEND ENDPOINT: GET /api/analytics/store-profiling?country=<optional>&period=<28|90>

For each store, compute a scorecard comparing the current period vs the immediately preceding period of equal length (e.g. last 28 days vs the 28 days before that). Return per store:

Identity: store, country, months_active (maturity from first sale date).
Sales KPIs (current vs prior, with % change): net revenue (KES), units, transactions (distinct order/customer count), ASP (avg selling price = net_sales/units), avg basket (net_sales / distinct transactions), UPT (units per transaction), discount rate (discounts_kes / gross_sales_kes), return rate (returned_item_quantity / ordered units).
Target performance: current-month target_kes, MTD actual, MTD-prorated target, % of target, projected month-end, variance.
Footfall & conversion: footfall count (current vs prior), conversion rate (transactions / footfall), footfall trend %.
Customer health: new vs returning split, repeat rate, distinct customers (current vs prior), % change.
Stock mix: units by range tier (NOOS/Core/Recent/New/Retired) from range_mgmt_store_tier_mix; flag if NOOS coverage is low or Retired/dead stock is high. Include weeks-of-cover if available.
Sell-through rate for the store (current period).

VERDICT LOGIC (compute a status + score per store):

Compute a 0–100 composite health score from weighted normalized signals: target attainment (30%), revenue trend vs prior (20%), conversion rate vs peer median (15%), sell-through (15%), customer repeat/retention (10%), stock-mix health — NOOS present & low dead stock (10%).
Status buckets: Healthy (score ≥ 70), Watch (50–69), At Risk (< 50). Use existing dashboard color conventions (green/amber/red).
Peer comparisons (conversion, ASP, basket) are computed within the same country (partition by country), like the tier logic does.

PAIN POINTS (the key ask — diagnose WHAT is wrong): For each store, generate a ranked list of specific, human-readable pain points with the supporting number, only when a threshold is breached. Examples of rules to implement:

"Revenue down X% vs last period" (if net revenue change < -10%)
"Tracking below target — projected Y% of month" (if projected < 90%)
"Low conversion: Z% vs country median W%" (footfall present but conversion below peer median)
"Falling footfall: down X%" (footfall trend < -10%)
"High discounting: X% of gross" (discount rate above country median + threshold)
"High returns: X%" (return rate > threshold)
"Weak NOOS coverage: only X% of stock is NOOS/Core" (core availability low)
"Dead/Retired stock heavy: X% of floor" (retired+aged tier share high)
"Low basket size: KES X vs country avg KES Y"
"Shrinking customer base: distinct customers down X%"
"Low repeat rate: X%"
Each pain point = {severity: high|medium|low, message, metric_value, benchmark}. Sort by severity. If no pain points, return a "No major issues" positive note.

Also return per store: 2–3 strengths (the inverse — what's going well: "Strong target attainment 112%", "Above-peer conversion", "Healthy repeat rate").
