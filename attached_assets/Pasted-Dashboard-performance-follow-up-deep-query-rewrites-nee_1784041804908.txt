Highest-value fix (biggest single win):
The Exec Summary at CTE at line 13754 scans all 1.5M rows of all_sales to build first-purchase-per-customer — but rollup_customer_first_purchase (172,833 rows, refreshed hourly) already holds that exact answer. There's a _rollup_fresh("customer_first_purchase") gate pattern used at line 4369 (in get_customers) that shows how to route this. Applying the same gate to this CTE should take Exec Summary from ~20s → ~1s.
The rollup has columns customer_id and first_purchase_date (DATE). Current CTE uses MIN(sale_date) where sale_date is TEXT, and the downstream comparison is a.first_ever BETWEEN '<date>' AND '<date>' (text). Confirm date-vs-text semantics match at boundaries before swapping in.
Second-priority fixes:

Sales-by-Hour: substring(o.created_at, 12, 2)::int is doing per-row string parsing on the full raw_shopify_orders table. Either extract hour to a generated column, or add an index on the computed expression, or pre-aggregate to a small hourly rollup.
Range Mgmt style×store CTEs: multiple queries computing 28-day sales windows over full history. Consider pre-aggregating into a rollup_style_store_recent table refreshed by the sync loop.
Overview country-summary: the sum-by-country query is doing full all_sales scans. If date range is bounded, idx_all_sales_country_date should be used — worth checking EXPLAIN.
