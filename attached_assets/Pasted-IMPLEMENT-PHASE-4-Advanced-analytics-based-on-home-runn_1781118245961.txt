Step 2: Replenishment accuracy tracking (full implementation)
Building on Phase 3's basic accuracy endpoint, add deeper analysis:

New endpoint GET /api/replenishment/forecast-accuracy:


For each completed replenishment (recommendation_actions where rec_type='replenish' and status='done'), measure actual vs recommended:

sqlactual_sold_28d = SUM(net_quantity) from all_sales
  WHERE pos_location_name = store
  AND variant_sku = sku
  AND sale_date BETWEEN acted_at AND acted_at + 28
recommended_qty = parsed from rec_key
accuracy_pct = 100 * actual_sold_28d / NULLIF(recommended_qty, 0)
bias = actual_sold_28d - recommended_qty  -- positive = under-replenished, negative = over

Aggregate by: store, subcategory, brand, month
Output includes mape (Mean Absolute Percentage Error) across all recommendations
Trend: is accuracy improving or worsening month-over-month?


New endpoint GET /api/replenishment/velocity-calibration:


Compare predicted weekly velocity (from the EWMA formula) vs actual subsequent 28-day sales
For each style active in the last 90 days: {style_name, predicted_weekly, actual_weekly_next4wk, calibration_error_pct, direction}
Flag styles where the EWMA is systematically over/under-predicting
This feeds back into improving the velocity formula over time

Step 5: Size health deep-dive

New endpoint GET /api/analytics/size-gaps:
