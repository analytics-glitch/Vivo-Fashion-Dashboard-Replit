---
name: Product Workspace guidance
description: Durable cross-cutting rules for the standalone Product Workspace.
---

- EOS/L10 meeting data is owned by the Product Workspace; migrate legacy public records once, then workspace edits own future status.
- Reference-library content is idempotently seeded, server-admin-gated for edits, and rendered through safe structured tables.
- Startup readiness and identity bootstrap must continue if PostgreSQL is temporarily unavailable; optional DDL cannot block the app shell. Business-critical data migrations must run before the optional-migration queue in the degraded path.
- Every style surface must server-scope to Vivo, Safari by Vivo, Safari, and Zoya. Development and assortment views each use their appropriate authoritative source rather than mixing product domains.
- Date of birth is Settings-admin-only: public team/birthday payloads must never include it.
- Embedded HTTPS previews require Secure/SameSite=None cookies; public feedback stores a canonical style number and colourway.
- Once a Range Plan matrix replacement migration is marked complete, gate incompatible legacy row seeders before they insert. Keep later startup seeding non-destructive for editable plan assumptions and rows.
- Garment-unit metrics are discrete counts: display and headline totals use whole units, while genuinely averaged metrics may retain one decimal. Production-order source quantities can be fractional, so round only after aggregation and keep upstream fractional-row validation separate.
- Weekly Order Plan targets and counts come from workspace plan rows; BI/Odoo orders are optional actuals enrichment and must not prevent the saved plan from rendering.
- Subcategory fabric-consumption rates are Workspace-owned planning references. Their own endpoints must self-heal lightweight schema/seeds because the full startup initializer can time out before late DDL. Business-confirmed rates outrank evidence-derived confidence without erasing historical context.
- Fabric-consumption applicability is a stored subcategory flag, not a page-name filter. Corrective seeds migrate only the known old seed signature so later planner edits remain authoritative.
- “Range Refreshed” stays a distinct saved/displayed order type but counts as new in every newness metric. Normalize `new`, Range Refreshed spelling variants, and `rr` through one shared rule; never also count `rr` as reorder.
- Range Refreshed also resets lifecycle evidence at its latest planned ISO week: first sale, lifetime sell-through, order count, and last-order age restart there; parent-style history never drives graduation.
- `Repeat` is the canonical non-new order type. Preserve migrated Re-order/Replenishment source labels and split Range Plan values in hidden legacy fields; keep old API keys as aliases, never as additive totals.
- Treat the shared BI product-workspace source as a completeness contract: route-specific projections must be versioned and field-audited before any payload reduction. Cold Assortment latency is dominated by BI source generation, not JSON serialization or React filtering.
- Assortment cards must receive an authoritative image endpoint and rely on native lazy loading. Do not probe a fallback image for every card on mount; cache successful private images for days and missing images long enough to prevent retry storms.
- Shared commercial facts must load from a version-checked durable last-good snapshot. Refresh after port bind (including degraded startup), claim refreshes with owned leases, and retry quickly only while no valid snapshot exists.

**Why:** The workspace shares users, product data, and deployment infrastructure with the BI environment, so accidental cross-brand data, private profile leakage, or a startup-time database wait is especially disruptive. A migrated monthly matrix was once joined by retired template rows because the old generic seed ran before checking the completed-migration marker. The full schema initializer can exceed its readiness timeout while still applying DDL, leaving a new column present but its later seed migration unapplied if that migration only lives in the normal path or behind slow optional migrations. The Weekly Order Plan once returned 503 during a BI outage even though its saved target rows were healthy. Fabric references need editorial review before they are allowed to influence production planning; one late consumption migration was skipped repeatedly until its endpoint became self-healing. Non-fabric taxonomy rows made the reference look incomplete, while unconditional corrective updates would have silently reset later planner decisions. Range Refreshed was historically omitted from some exact-`new` checks and included in an `rr` reorder check, understating newness. Removing old Range Plan response keys previously crashed existing consumers, and collapsing split repeat values without legacy fields would erase audit evidence. A measured 5.59 MB BI document took 46–97 seconds to generate while Assortment serialization took about 1 ms; eager fallback probes also produced hundreds of avoidable requests. The workspace schema initializer also regularly exceeds its 15-second budget, so scheduling a snapshot warmer only from its success callback leaves cold starts permanently unwarmed.

**How to apply:** When extending Product Workspace, retain the server-side brand/privacy gates and keep startup/preview behavior resilient before adding new page features. For Range Plan seed-shape changes, use a transactional one-time marker, gate old seeders before insertion, run critical lightweight migrations first in both normal and degraded startup paths, and verify row counts after a second restart. Render saved weekly targets with empty/stale actuals when the BI source is temporarily unavailable. Start durable commercial snapshot loading independently immediately after the HTTP port binds; publish only validated complete documents, preserve all source keys, and never let an expired refresher overwrite a newer claim. Keep maintained fabric-rate seeds insert-only, make their GET/PATCH path ensure readiness, filter the table by its stored non-garment flag, and constrain corrective updates to the exact obsolete seed state. Derive confidence from order evidence unless explicitly estimated or business-confirmed, and do not consume these values in planning math without a separate approved change. Route every newness calculation through the shared order-type classifier while preserving original labels. New writes use Repeat; compatibility keys mirror the full Repeat value in one key and zero in the other so old consumers cannot double-count. Preserve every shared-source key until each consumer is moved to a versioned route contract; optimize with request overlap, caching, code splitting, and memoization first. For catalogue grids, assign one authoritative image URL per style and let viewport proximity trigger the request.
