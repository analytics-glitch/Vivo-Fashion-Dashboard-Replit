---
name: Project Reconnect one-off cohort export
description: Pattern for building a standalone, brief-defined cohort/test-allocation export without touching canonical churn logic.
---

- A one-off business-brief export (its own cohort boundaries, value bands, sample sizes) must NEVER alias the platform's canonical churn/lifecycle constants (e.g. `CUSTOMER_AT_RISK_MIN_DAYS`, `CUSTOMER_CHURN_DAYS` in `api_pg.py`) even when the concepts overlap — give it fully separate, private constants (this task used a `PR_*` prefix) so a future change to one never silently changes the other.
- `all_customers` has no wholesale/staff flag anywhere. Any bulk customer export needing that exclusion has to fall back to a best-available heuristic (company email-domain regex) and must say so explicitly in its output — it is not equivalent to a hand-curated exclusion list from an old source system.
- `_not_walkin_pseudo_sql(alias)` (api_pg.py) already returns the FULL `alias.customer_id NOT IN (...)` predicate — call it once against the sales-row alias inside the lifetime-value CTE. Do not also wrap `all_customers` rows in a second exclusion CTE; that misuses the helper (it's built to prefix an alias, not to stand alone as a raw condition) and is redundant.
- Sequential, without-replacement, multi-test allocation across a limited pool: tests that restrict eligibility (e.g. has-email-only) but are scheduled LATE in a long sequential draw order can be starved by earlier *unrestricted* draws that happen to consume members of that same restricted subset, even though those earlier draws aren't targeting it. Instrument the allocator to record the eligible-pool size immediately before each restricted test's own draw, and put that number (not the original population total) in the shortfall explanation — it's the only way the reported shortfall is actually explicable to a reader.
- When a brief's literal recency-boundary instruction (e.g. "<182 days = Excluded, no lower bound") is recomputed against live data and lands far from an old reference figure, the most likely explanation is that the *old* reference list was implicitly pre-scoped in a way the literal brief text doesn't state (e.g. excluded very-recently-active buyers a reactivation list wouldn't have included). Keep the literal instruction, but name this reasoning explicitly in the QA output rather than silently reverse-engineering the old number.
